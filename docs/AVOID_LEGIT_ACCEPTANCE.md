# 避障 Legit（拟真）验收标准与评分卡

> 版本 v1.1 · 2026-10-02 · 适用 v1.2.5
> 配套：[`AVOID_TECHNICAL_DOCUMENTATION.md` 6.8](AVOID_TECHNICAL_DOCUMENTATION.md#68-legit-代理实现说明v120)、[`AVOID_STAGE3_LEGIT_REPORT.md`](AVOID_STAGE3_LEGIT_REPORT.md)
> 用途：**"拟真"到底做到什么程度算好**——给每一档能力一个可测量、可复现、可回归的判据，
> 而不是靠"感觉还行"。红色项就是本阶段还没做完的事。

---

## 0. 定位（先定标准，再谈好坏）

参考实现的原文就是最好的定位：

> Legit: **subtle assistance while maintaining a natural playstyle** —— "subtly modifies inputs",
> "**relies partially on user skill and can sometimes fail**"

翻译成本项目的三条公理：

1. **它是安全带，不是代驾。** 语义永远是"阻止你走进危险"，不是"帮你走图"。
2. **它允许失败。** 没有干净解的时候，**不动手**优于"花哨地救一下"。
3. **它的成功标准是"你几乎没注意到它"。** 被注意到 = 干预过强，即使那一次确实救了命。

## 1. 五条设计原则（冲突时按此优先级裁决）

| 优先级 | 原则 | 一句话 | 反例（违反时你会看到） |
| ---: | :--- | :--- | :--- |
| 1 | **不造成伤害** | 任何接管都必须比"玩家自己继续按"活得更久，永不更差 | 接管之后反而更快死 |
| 2 | **不打扰** | 安全局面零干预；玩家一恢复安全输入，下一帧就交还 | 贴边走路被莫名减速 |
| 3 | **最后一刻出手** | 在"再不动手就来不及"的那一帧才介入，而不是"一看见危险"就介入 | 离黑水还有 2 格就刹车/起跳 |
| 4 | **动作由轻到重** | 方向键 > 松/按钩 > 跳跃；跳跃是最后手段 | 勾着墙被拖向黑水时起跳 |
| 5 | **可调且忠实** | 每个滑块都有单调、可观察、可复现的效果 | 拉滑条没感觉 / 拉满行为不变 |

> 原则 3 是"拟真"与"Basic"最大的分野：Basic 是"能早就早"，Legit 必须像人一样**等到最后一刻**。

## 3. 人类手感评判（三分钟流程，不需要看日志）

**测试 1 · 隐形测试（最重要）**
在一张有黑水/冻结块的图上正常玩 3 分钟，**不要刻意靠近危险**。数一下你"注意到代理动了"的次数：
* 0–1 次 → 合格；2–3 次 → 偏吵（多半是 B2 提前量太大）；≥ 4 次 → 不合格。
> 判据的哲学：安全带不会在你正常开车时提醒你它的存在。

**测试 2 · 最后一刻测试**
朝黑水走但**慢慢走 / 走走停停**。期望：直到你几乎确定"再不收手就进去了"，代理才动手；
只要你一停下来，它立刻放手（下一次按键它就是隐形的）。

**测试 3 · 勾索测试**
勾住墙、按住钩被拖向黑水，然后再勾向带黑水的竖直墙。
期望：**先松钩 + 反方向键**；不要起跳；松钩的时机应接近"再晚就来不及"。

**测试 4 · 优先级测试**
`Life priority` 拉满 → 明显更保守（宁可改输入也要活）；归零 → 明显更贴你的输入。
`Radius` 依次 12 → 4 → 2 → 1（半格）→ 介入一次比一次晚，1 基本等于关闭。

**测试 5 · 反向测试（防止过度拟合）**
站在黑水边**不动**、在窄通道里**直行**、在安全平台上**跳跃**：
期望：**完全不干预**（0 次接管、0 次鬼畜跳）。

## 4. 当前未达标项 → 建议的下一步

### ❌ B2 / D4：介入提前量太大（"最后一刻原则"还没实现）

**现象**：现在只要"玩家输入会在 `kick_in_ticks`(20) 内致死"且"危险进了感知范围"，代理就在**那一帧**出手。
半径越大、出手越早（半径 12 时提前约 19 帧 = 0.38 s），这就是你三次反馈的共同根源。

**建议规则（属于 Legit 范围内，不涉及瞄准）**：

> 对每个可行方案 P，用同一套模拟器算出**最晚可行帧 d\***：从当前局面先按玩家输入走 d 帧，再执行 P，
> 仍然能活满窗口的最大 d。**只在 `d* == 0` 的那一帧才接管。**

* 效果：介入永远发生在"再不动手就真来不及"的那一刻；玩家停手/转向时代理永不出现；
* 半径滑块退回它本来的角色（限制搜索范围 + 极端情况兜底），不再直接决定"多早动手"；
* 成本：每个候选多做几次模拟（可复用现有 rollout 循环），quality 24 的余量足够；
* 代价：延迟期间玩家输入仍可能把局面变得更糟 —— 所以判据里要有 1–2 帧的安全余量
  （`d* - 1`），离线用例要覆盖"延迟一帧仍然成功"。

**验收**：B2 全部落入目标区间（方向 5–8 帧、松钩 3–8 帧、跳跃 ≤ 2 帧），测试 1 的"注意到次数"降到 0–1。

### ⚪ B3 / B4 / B5 / C1 / C4：手感指标还没有仪表

**台架已经落地**（v1.2.3）：`CAvoidLegitTest.ParameterSensitivitySweep` 会跑一个"走神玩家"脚本，
输出存活 / 死亡帧 / 接管帧数 / 动作分布 / **提前量** / 耗时，并且逐档扫描每个滑条 —— 这就是 B2、B3、C1 的仪表：

```bash
./build/testrunner --gtest_filter='CAvoidLegitTest.ParameterSensitivitySweep' 2>&1 | grep avoid-params
```

还缺的是"正常跑图"的接管率（需要一段真实或录制的输入回放），以及抖动检测（B5/C4）。

### ⚪ A1 / E4：游戏内验收仍需人工跑一遍

见 [8.3b](AVOID_TECHNICAL_DOCUMENTATION.md#83b-legit-代理验收v120-起)；离线能证明的都已在 25 个用例里。

## 6. 允许失败（预期内的失败，不算 bug）

1. 没有任何方案能活满前瞻（NSIF 或干脆不动手）；
2. 只有靠瞄准才能救的局面（坠落时自动出勾挂墙 → 需要阶段四的瞄准）；
3. 喷气背包 / 钩住玩家 / 飞锤深飞中（红线：不动手，只报理由）；
4. 玩家输入本身安全的任何时刻（哪怕旁边就是黑水）。
